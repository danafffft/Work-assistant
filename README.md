# Work Assistant

Windows-застосунок для **класичного Outlook**. Підключається до вже налаштованого профілю через Outlook COM: окремі реєстрація, Entra ID і передача пароля не потрібні.

## Запуск на Windows

1. Встановіть Python 3.12+ із [python.org](https://www.python.org/downloads/windows/) і класичний Outlook. Відкрийте Outlook та переконайтеся, що робоча пошта працює.
2. Завантажте цей репозиторій. Запустіть `Start-WorkAssistant.bat` подвійним клацанням. Він створить `.venv`, встановить `pywin32` і `pywebview`, відкриє окреме вікно.
3. Натисніть **«Підключити Outlook»**. Використовується основна скринька поточного профілю Outlook.

Потрібні доступ до PyPI для першої установки та Microsoft Edge WebView2 Runtime (зазвичай уже є у Windows). Якщо Outlook показує системний запит доступу, перевірте його та дотримуйтеся правил вашої організації. Новий Outlook, Mac та браузерний Outlook через COM не підтримуються.

Ручний запуск:

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-windows.txt
.venv\Scripts\python.exe desktop.py
```

Це запуск із вихідного коду, не готовий інсталятор `.exe`. Адміністратор організації може блокувати програмний доступ до Outlook.

## Інтерфейс

- Чорне бічне меню, вівсяний фон `#F0E6DA`, вершкові акценти `#FFEDAB`, вишневі кнопки `#75070C`, оливкові індикатори `#4F6815`.
- Категорії: люди, звіти, навчання, автоматичні повідомлення, спільна категорія «Jira та Confluence».
- Пріоритети, пошук, окрема панель людей, перегляд вибраного листа та відкриття оригіналу в Outlook.
- Розділ «Наради» показує запрошення серед завантажених листів, а не повний календар.

## Що саме робить агент

Оновлення завантажує до **100 останніх елементів основної папки Inbox**. Категорії й пріоритети визначаються локальними правилами адреси та теми (`classify()` в `app.py`). Категорія «Від людей» потребує відображуваного імені з 2–4 слів із великих літер, без системних назв. ManageEngine / OpUtils / Rogue Detection та системні alert-повідомлення потрапляють до автоматичних навіть із персональним ім’ям відправника. Невизначені відправники також потрапляють до автоматичних. Це евристика: справжня людина з коротким або нестандартним ім’ям може не пройти фільтр; ім’я не доводить особу відправника. «Jira та Confluence» — спільна категорія листів обох сервісів, не інтеграція з їх API. При збереженні категорій старі окремі мітки «Jira» та «Confluence» замінюються актуальною категорією; сторонні мітки зберігаються.

Категорія **«Звіти»** — усі листи з прикріпленими файлами, незалежно від теми чи відправника. Вона має пріоритет над категоріями людей, Jira та іншими. Вбудовані картинки підпису та приховані вкладення Outlook не враховуються. Файли не завантажуються й не відкриваються автоматично.

Кнопка «Зберегти категорії» після підтвердження записує категорію та importance для **всіх завантажених листів**, незалежно від фільтрів. Інші категорії зберігаються. Листи не переміщуються та не видаляються. При частковій помилці раніше виконані зміни залишаються, лічильник показує прогрес.

Після підключення та під час кожного оновлення запрошення автоматично перевіряються за основним календарем тієї самої скриньки. Якщо час вільний — організатору **надсилається прийняття**. Інші зайняті, tentative й out-of-office події блокують прийняття; власна попередня копія запрошення не вважається конфліктом. Повторювані, цілоденні, минулі події, помилки доступу залишаються для ручного перегляду. Інші календарі не перевіряються. Зміна календаря між перевіркою й відповіддю все ще можлива.

Автооновлення працює кожні 30 секунд, поки відкрите вікно застосунку; є кнопка паузи. У сплячому режимі комп’ютера оновлення не працює. Поки немає ручного редагування правил через інтерфейс, вибору додаткових скриньок та встановлювача. Закриття вікна завершує локальний сервер і автоматичну обробку. Якщо Outlook ще не створив календарну копію запрошення, застосунок створює її для перевірки; відповідь надсилається лише після перевірки конфліктів. Пошта не надсилається сторонньому AI-сервісу; уривки залишаються в пам’яті локального застосунку.

## Демонстрація та розробка

На Linux або без Outlook:

```sh
python3 app.py
```

Відкрийте локальний порт 8000 у своєму браузері. Вбудовано демонстраційні листи. Не відкривайте локальний HTTP-сервер у загальний інтернет. У Windows-застосунку використовується випадковий локальний порт.

Збережено альтернативний Microsoft Graph backend для розробки: `MICROSOFT_CLIENT_ID`, `MICROSOFT_CLIENT_SECRET`, необов’язкові `MICROSOFT_TENANT_ID` (типово `common`) і `MICROSOFT_REDIRECT_URI` (типово `http://localhost:8000/auth/callback`). Потрібні Web app registration та delegated дозволи `User.Read`, `Mail.ReadWrite`, `Calendars.ReadWrite`. Вхід — `/auth/login`; у стандартному Windows-сценарії він не потрібен. Токени лише в пам’яті, без автоматичного оновлення. Секрети не зберігайте в Git.

## Перевірки

```sh
python3 -m unittest discover -s tests -v
node --check web/app.js
```

Юніт-тести перевіряють правила сортування та календарні рішення з підміною COM/Graph. Реальне COM-підключення потребує Windows, Outlook і налаштованої скриньки; у Linux воно не перевірене. Реальні відповіді на наради в тестах не надсилаються.


## Робочий графік та задачі Jira

У меню є **«Робочий графік»**: календарні події основної скриньки на 7 днів та чернетка блоків роботи над задачами. Типовий графік — понеділок–п’ятниця, **09:00–18:00, Europe/Kyiv**, обід 13:00–14:00. Часові межі можна змінити змінними `WORK_START_HOUR`, `WORK_END_HOUR`, `WORK_TIMEZONE`. Для Windows дані часових поясів встановлюються разом із залежностями.

План не змінює календар. Задачі сортуються спочатку за дедлайном, потім за пріоритетом Jira та розкладаються блоками до 60 хвилин поза зайнятими зустрічами, обідом і вихідними. Береться remaining estimate Jira; без оцінки резервується 60 хвилин. Оцінки довші за 40 годин обмежуються 40 годинами в цьому плані. Невміщені задачі показуються окремо, блоки після дедлайну позначаються. План повністю перераховується під час оновлення, тому ручний прогрес і закріплення блоків поки не підтримуються.

### Підключити Jira

1. Відкрийте «Профіль і підключення».
2. Вкажіть адресу сайту своєї Jira та спільний робочий email. Значення вводяться лише в застосунку й зберігаються у локальному профілі, не в коді.
3. Для Jira Cloud (`*.atlassian.net`) введіть email та API token; для Jira Server/Data Center — персональний access token, який ваша організація дозволила використовувати. Пароль у застосунок не вводиться. Scoped tokens, що потребують `api.atlassian.com/ex/jira/...`, поки не підтримуються.
4. Натисніть «Зберегти профіль». Токен зберігається лише в пам’яті до відключення Outlook/закриття сервера. Поле токена очищається після надсилання. Після перезапуску введіть повторно.

Альтернатива: змінні `JIRA_URL`, `JIRA_API_TOKEN`, `JIRA_EMAIL` до запуску. Не додавайте їх значення до Git та не надсилайте в чат.

JQL: `assignee = currentUser() AND statusCategory != Done` — призначення визначається за власником токена, не за порівнянням імен. Завантажується до 1000 задач із пагінацією; перевищення ліміту позначається. Помилка Jira не видається за порожній список: джерело показує помилку. Якщо календар не вдалося прочитати, новий план не складається. VPN/доступ до корпоративної Jira має вже працювати на вашому комп’ютері. Токен не пересилається на інші адреси при HTTP-переадресації.

**Teams відкладено за вибором користувача.** Повідомлення Teams наразі не читаються та до графіка не додаються. Для майбутнього підключення потрібні дозволений Microsoft Graph доступ і окремий вхід; COM Outlook доступу до чатів не надає.

Автооновлення — періодичне опитування, не push-події. Строк життя поточного Outlook-сеансу — 24 години; після цього потрібне повторне підключення. Реальний COM/корпоративний Jira доступ перевіряється на Windows із вашим профілем, а не в Linux-середовищі розробки.

## Локальний профіль

Екран «Профіль і підключення» зберігає спільний email та адресу Jira у `%LOCALAPPDATA%/WorkAssistant/profile.json` (Windows), поза репозиторієм. Токени й паролі до файлу не записуються. Це локальний профіль, а не обліковий запис у хмарному сервісі. Outlook використовує поточний MAPI-профіль, Jira — окремий API-токен. Однакова пошта не надає автоматичного доступу до сервісів. Після зміни email або адреси Jira попередній токен скидається.
